NeonDB ашиглаж болох уу?

Болно. CMS-ийн контентод тохиромжтой бөгөөд эхний шатанд үнэгүй tier хангалттай. Апп-даа pooled connection, migration-д direct connection ашиглана. Харин зураг болон PDF-ийг Neon-д хадгалахгүй. Binary файл өгөгдлийн санг томруулж, backup-ыг удаашруулдаг тул DB-д зөвхөн файлын URL ба metadata-г хадгална.

Зураг хадгалахад юу хэрэгтэй вэ?

R2 bucket-ыг клиентийн Cloudflare бүртгэл дээр үүсгэнэ. Upload хийх үед EXIF/GPS мэдээллийг автоматаар устгана, учир нь зураг авсан байршил ил гарч болно. AVIF/WebP хэлбэрээр 480, 960, 1600 px хэмжээтэй хувилбаруудыг үүсгэнэ. Alt текстийг хоёр хэл дээр заавал бөглүүлнэ. Файлын нэрийг санамсаргүй тэмдэгтээр өгч хүний нэр оруулахгүй. Гишүүдийн зураг оруулахад өсвөр насны гишүүн болон эцэг эхийн зөвшөөрлийн талбаруудыг бөглөхгүй бол нийтлэх боломжгүй байна. Илүү хялбар хувилбар хэрэгтэй бол Vercel Blob ашиглаж болно.

Google Sheet-ийг яаж аюулгүй холбох вэ?

Case log-ийг клиентийн хувийн spreadsheet-д үлдээнэ. Тусдаа "public totals" spreadsheet үүсгээд IMPORTRANGE ба формулаар зөвхөн нийт дүнг тооцоолно. Service account-д зөвхөн энэ хоёр дахь файлд Viewer эрх өгнө. Ингэснээр код алдаатай байсан ч case-level мөрүүд сайт руу хэзээ ч хүрэхгүй.

Ашиглах заавар

Claude Code дээр хэрхэн ажиллуулах вэ

  2. Тэр folder дотроо терминалаас claude командыг ажиллуулна.

  3. Phase бүрийн prompt-ыг Хуулах товчоор хуулж, шинэ session-д (/clear) оруулна. Нэг session-д нэг phase хийхэд context цэвэр байна.

  4. Phase бүр дуусахад checklist-ийг шалгаж, pnpm dev дээр өөрөө нүдээр харсны дараа дараагийн phase руу шилжинэ.

Суурь бүтэц

Next.js, хоёр хэлний маршрут, дизайн token, фонт, хүртээмжийн суурь.

Prompt · Phase 1
Read CLAUDE.md fully before doing anything. We are doing PHASE 1 — Scaffold. Do not start later phases.

Create a Next.js project (App Router, TypeScript strict, pnpm) with Tailwind CSS and next-intl.

Requirements:
- Locales mn (default) and en, URL prefixes /mn and /en. Middleware redirects / to /mn (respect Accept-Language only on first visit).
- <html lang> set per locale.
- LanguageSwitch component on every page that links to the SAME path in the other locale, is a real <a> link, keyboard reachable, and labelled in both languages.
- Skip-to-content link, semantic header/nav/main/footer landmarks, visible focus styles.
- Header nav: Нүүр, Нөлөөлөл, Аргачлал, Судалгаа, Бодлого, Бидний тухай (English equivalents in en). Mobile menu must work without JS hover and be keyboard operable.
- Footer: contact email from env shown as selectable text, language switch, copyright.
- Design tokens as CSS variables (light + dark via prefers-color-scheme): ink neutrals, honey/amber accent used sparingly, AA contrast checked. Wire tokens into Tailwind theme.
- Fonts via next/font/google with cyrillic + latin subsets: Unbounded (display headings only), IBM Plex Sans (body), IBM Plex Mono (figures, citations). Use font-variant-numeric: tabular-nums for numbers.
- Placeholder pages for home, impact, methodology, research, policy, about — content marked [ХҮЛЭЭГДЭЖ БУЙ / TBD].
- All UI strings in messages/mn.json and messages/en.json. No hardcoded strings in components.
- Tooling: ESLint, Prettier, Vitest, Playwright. Scripts: dev, build, lint, typecheck, test, e2e.
- .env.example with NEXT_PUBLIC_SITE_URL and NEXT_PUBLIC_CONTACT_EMAIL. Never hardcode a domain.

When finished: run lint, typecheck, test and build; fix failures; add one Playwright test that the language switch keeps the path; commit "phase 1: scaffold".
02

CMS, Neon, R2

Кодгүйгээр засах admin, контентын загвар, зургийн аюулгүй байдал.

Prompt · Phase 2
Read CLAUDE.md. PHASE 2 — Payload CMS on Neon with R2 media. Do not start later phases.

Install Payload CMS 3 into this Next.js app, admin at /admin.
- DB: @payloadcms/db-postgres. DATABASE_URL = Neon pooled URL (app), DATABASE_URL_UNPOOLED = direct URL (migrations). Use generated migrations, not schema push, for production.
- Localization: mn (default, fallback) and en.
- Storage: @payloadcms/storage-s3 pointed at Cloudflare R2 (R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET, R2_PUBLIC_URL). No file bytes in Postgres.

Collections:
- Users: admin/editor roles, no public sign-up.
- Media: required localized alt (mn + en). Field subject: none | adult member | teen member. If "teen member": consentTeen, consentParent (checkboxes, both required true), consentDate, consentRecordRef — block publishing otherwise. Strip ALL EXIF/GPS metadata with sharp. Generate AVIF + WebP at 480/960/1600. Store files under random slug names, never personal names.
- Papers: title, slug, abstract (rich text), authors, year, venue, doi, status, pdf (upload), codeUrl, dataUrl. Auto-generate APA and BibTeX strings in a hook.
- Team: name, role, bio, photo. Required checkbox "confirmedAdult18Plus" — only adults are listed publicly; minors are never listed individually.
- Partners: name, logo, url.

Globals:
- Site: mission line, contact email, social links, default SEO, organization schema fields (legal name, founding date, address city).
- Methodology: sources[], definitions[] and countingRules[] each with a stable anchorId, limitations, changeLog[] {date, summary}.
- Policy: summary, fullText (rich text), status (drafted | submitted | under review | adopted | rejected), statusDate, history[].
- ImpactSnapshot: json + fetchedAt, read-only in admin.

Every collection and global gets a localized SEO group (metaTitle ≤ 60 chars, metaDescription ≤ 160 chars, with admin character counters).
Access: public read only for published docs. Enable drafts + versions for Papers, Methodology and Policy.
afterChange hooks call revalidatePath for both locales of affected routes.
Seed script with clearly marked placeholders only — no invented people, numbers or partners.
Write docs/README-editor.md IN MONGOLIAN for a non-coder: log in, edit page text, add a paper with PDF, update policy status, add a change-log entry, upload a photo with consent.

Run lint/typecheck/test/build, fix failures, commit "phase 2: cms".
03

Impact өгөгдлийн урсгал

Sheet → шалгалт → 5-аас бага бол нуух → snapshot → өдөр бүрийн шинэчлэл.

Prompt · Phase 3
Read CLAUDE.md, especially "Impact data contract". PHASE 3 — Impact data pipeline. Do not build page UI yet.

Implement src/lib/impact/:
- client.ts: Google Sheets API v4 with a read-only service account (GOOGLE_SA_EMAIL, GOOGLE_SA_PRIVATE_KEY, IMPACT_SHEET_ID). Read ONLY the ranges Totals!A:H and Monthly!A:D. Use the "spreadsheets.readonly" scope.
- schema.ts: zod schemas for both tabs. If validation fails, reject the whole fetch.
- suppress.ts: one pure function. n_cases < 5 or missing → value null, suppressed true. Apply to each total AND each monthly point individually. Never compute a total by summing cells; use the sheet's own totals so suppressed values cannot be back-calculated.
- index.ts: getImpact(locale) → { metrics, monthly, fetchedAt, stale }. Uses fetch caching with revalidate 86400 and tag "impact". On success, save the validated + suppressed result to the ImpactSnapshot global. On failure, return the last snapshot with stale: true.
- Never log row contents or values — log only error type and timestamp.

Also:
- app/api/revalidate/route.ts: POST with header x-revalidate-secret (REVALIDATE_SECRET) → revalidateTag("impact"). 401 otherwise.
- vercel.json cron: daily at 22:00 UTC (06:00 Ulaanbaatar) calling the route (use CRON_SECRET per Vercel docs).
- Vitest unit tests with fixtures: n=4 suppressed, n=5 shown, missing n suppressed, bad schema rejected, failure falls back to snapshot, monthly suppression independent.
- Document the two tabs, with an example row each, in docs/impact-sheet.md (Mongolian + English).

Run lint/typecheck/test, fix failures, commit "phase 3: impact pipeline".

Хуудсууд ба дизайн

Зургаан хуудас, тоо бүр нотолгоо руугаа холбоостой.

Prompt · Phase 4
Read CLAUDE.md, especially "Design direction". PHASE 4 — Pages and visual design. Server Components first; "use client" only for copy buttons and the mobile menu.

Pages (all content from Payload + getImpact; nothing hardcoded):
- Home: one-line mission; the four metrics where show_on_home is TRUE — large tabular numerals or the suppressed label, the "as of" date, and a link "Хэрхэн тоолсон бэ? / How is this counted?" to the methodology anchor; short cards linking to the other pages.
- Impact: every metric with value (or suppressed label), as-of date, method link. Monthly trend chart as server-rendered SVG: gaps for suppressed months (not zero), labelled axes, colors from tokens so it works in both themes, role="img" with a text summary, plus the full data as a <table> inside <details>. Show "Сүүлд шинэчлэгдсэн" time and a visible notice when stale is true.
- Methodology: data sources (NSO/ILO Child Labour Survey 2021–22, Labour Force Survey 2022, NGO case log) with links; definitions and counting rules rendered with their anchorId as id; limitations; dated change log, newest first.
- Research index + research/[slug]: abstract, buttons for PDF / code / data, citation block with APA and BibTeX and copy buttons, year and venue.
- Policy: summary, status badge with date, history as a vertical timeline, full text with a table of contents.
- About: founder, team (adults only), partners with logos, contact email as selectable text + copy button. No contact form.

Design: calm, evidentiary, institutional — like a statistics office, not a charity campaign. Ink neutrals, honey accent used sparingly, at most ONE subtle hexagon motif (e.g. metric markers). Generous whitespace, 65ch text width, clear type scale. No stock photos of children. Mobile-first: verify at 360px, 768px, 1280px. next/image with correct sizes and priority only on the LCP image.

Run lint/typecheck/test/build, fix failures, commit "phase 4: pages".
05

SEO ба analytics

Metadata, hreflang, sitemap, schema.org, Search Console, Plausible.

Prompt · Phase 5
Read CLAUDE.md. PHASE 5 — SEO and analytics. All URLs built from NEXT_PUBLIC_SITE_URL.

- generateMetadata on EVERY route, from the CMS SEO group with fallback to Site defaults. Title template "%s | Ажилчин Зөгий" (localized). description, canonical, alternates.languages { mn, en, x-default → en }, openGraph (locale mn_MN / en_US, image), twitter summary_large_image.
- app/sitemap.ts: every page and every paper in both locales, with alternates.languages and lastModified from CMS updatedAt.
- app/robots.ts: allow all, disallow /admin and /api, link to the sitemap.
- JSON-LD components (src/lib/seo/jsonld.ts, typed):
  • NGO (Organization subtype) + WebSite on every page — name in both languages, logo, email, sameAs, foundingDate from the Site global.
  • Person for the founder on About (worksFor → the NGO).
  • ScholarlyArticle on each paper (author, datePublished, abstract, url, encoding → PDF), plus Google Scholar meta tags: citation_title, citation_author, citation_publication_date, citation_pdf_url.
  • Dataset on Impact (name, description, temporalCoverage, dateModified = fetchedAt, isBasedOn → the sources).
  • BreadcrumbList on inner pages.
- Dynamic OG images per page with next/og, using a Cyrillic-capable font.
- Google Search Console verification meta from NEXT_PUBLIC_GSC_VERIFICATION.
- Plausible via next/script (NEXT_PUBLIC_PLAUSIBLE_DOMAIN); custom events for PDF downloads and outbound clicks. No cookies.
- Unit tests that JSON-LD output is valid JSON with the required fields and that every route returns a non-empty title and description in both locales.

Run lint/typecheck/test/build, fix failures, commit "phase 5: seo".
